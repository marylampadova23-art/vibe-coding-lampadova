# Feedback Bot — Lab3

Telegram-бот для сбора обратной связи после обучения, работы с каталогом обучений из CSV и облачного запуска в Railway.

## Что изменено по обратной связи пользователей

После тестирования реальными пользователями были внесены два улучшения.

### 1. Понятный формат даты

Даты из `trainings.csv` по-прежнему хранятся в формате `YYYY-MM-DD`, но бот показывает их пользователю в привычном виде.

Пример:

```text
2026-10-05 → 5 октября 2026 года
```

Если дата в CSV имеет неожиданный формат, бот не падает и показывает исходное значение.

### 2. Кнопки для каталога обучений

Команда `/trainings` больше не отправляет сразу длинный список.

Сначала бот показывает inline-кнопки подразделений, которые автоматически собираются из `trainings.csv`, а также кнопку **«Все обучения»**.

После выбора пользователь получает только нужную часть каталога.

Текстовая команда `/department <отдел>` при этом сохранена.

## Возможности

Бот умеет:

- собирать отзывы через `/feedback`;
- сохранять отзывы в SQLite;
- отправлять уведомления руководителю;
- показывать статистику через `/report`;
- читать каталог обучений из `trainings.csv`;
- показывать каталог через кнопки по подразделениям;
- искать обучение по части названия;
- фильтровать каталог командой `/department`;
- работать в Railway через polling;
- хранить SQLite-базу на Railway Volume через `DATA_DIR`.

## Команды

- `/start` — описание бота и список команд
- `/help` — помощь
- `/feedback` — оставить отзыв
- `/skip` — пропустить комментарий
- `/cancel` — отменить заполнение
- `/report` — отчёт для руководителя
- `/myid` — показать Telegram ID
- `/trainings` — открыть каталог с кнопками подразделений
- `/training адаптация` — найти обучение по названию
- `/department HR` — показать обучения подразделения

## Структура trainings.csv

```csv
name,department,format,date,owner
Адаптация новых сотрудников,HR,Онлайн,2026-10-10,Анна Смирнова
```

Обязательные столбцы:

- `name` — название обучения;
- `department` — подразделение;
- `format` — формат обучения;
- `date` — дата;
- `owner` — ответственный.

## Требования

- Python 3.9+
- `python-telegram-bot==21.11.1`
- `python-dotenv==1.1.1`

Для чтения CSV используется стандартный модуль `csv`, поэтому новые зависимости для улучшений не потребовались.

## Локальный запуск

Создать и активировать виртуальное окружение:

```bash
python3 -m venv .venv
source .venv/bin/activate
```

Установить зависимости:

```bash
python -m pip install -r requirements.txt
```

Создать `.env` на основе `.env.example`:

```text
BOT_TOKEN=ваш_токен
ADMIN_ID=ваш_telegram_id
```

Запустить:

```bash
python bot.py
```

## Railway

Для облачного запуска сервис использует:

- Root Directory: `/lab3`
- Start Command: `python bot.py`
- `BOT_TOKEN` — токен Telegram-бота
- `ADMIN_ID` — Telegram ID руководителя
- `DATA_DIR=/data`
- Railway Volume, подключённый к `/data`

Бот работает через polling, поэтому отдельный webhook и публичный HTTP URL не требуются.

## Хранение данных

SQLite-база хранится по пути:

```text
$DATA_DIR/feedback.db
```

Локально, если `DATA_DIR` не задан, база сохраняется рядом с `bot.py`.

В Railway `DATA_DIR=/data`, поэтому база находится на постоянном Volume и сохраняется после redeploy.

## Безопасность

Настоящие значения `BOT_TOKEN` и `ADMIN_ID` не хранятся в GitHub.

Файлы `.env`, `.venv` и `*.db` исключены через `.gitignore`.

## Как проверить улучшения

1. Отправить `/trainings` — должны появиться кнопки подразделений и кнопка «Все обучения».
2. Нажать на подразделение — бот показывает только соответствующие обучения.
3. Проверить дату в карточке обучения — вместо `YYYY-MM-DD` отображается, например, `10 октября 2026 года`.
4. Проверить `/department HR` — старая текстовая команда продолжает работать.
5. Проверить `/feedback` и `/report` — функционал предыдущих лабораторных сохранён.
