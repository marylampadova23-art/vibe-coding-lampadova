Улучши моего существующего Telegram-бота на Python на основе обратной связи реальных пользователей.

Контекст:
Бот уже работает в Railway и используется через polling.
Он умеет:
- собирать обратную связь через /feedback;
- сохранять отзывы в SQLite;
- показывать отчёт через /report;
- читать каталог обучений из trainings.csv;
- показывать каталог через /trainings;
- искать обучение через /training <запрос>;
- фильтровать обучения через /department <отдел>;
- хранить SQLite-базу на постоянном диске Railway через переменную DATA_DIR;
- получать BOT_TOKEN и ADMIN_ID из переменных окружения.

Важно:
Не удаляй и не ломай существующий функционал.
Сохрани совместимость с текущим деплоем Railway.

По результатам тестирования были получены две основные точки улучшения.

1. Пользователю неудобен формат даты YYYY-MM-DD.
Нужно сделать даты более понятными для русскоязычного пользователя.

Например:

2026-10-05

должно отображаться как:

5 октября 2026 года

Создай отдельную функцию форматирования даты и используй её при отображении дат обучений из trainings.csv.

Если дата в CSV имеет некорректный формат, бот не должен падать — можно показать исходное значение.

2. Пользователь отметил, что команда /trainings формирует длинный текстовый список.
При увеличении количества обучений такой список будет неудобно просматривать.

Измени /trainings следующим образом:

- после команды /trainings показать пользователю кнопки с подразделениями, которые реально присутствуют в trainings.csv;
- добавить кнопку «Все обучения»;
- после нажатия на подразделение показывать только обучения этого подразделения;
- после нажатия «Все обучения» показывать полный каталог;
- использовать inline-кнопки Telegram;
- список подразделений получать из CSV автоматически, а не прописывать вручную;
- сохранить существующую текстовую команду /department <отдел> — она должна продолжить работать.

Требования:
- использовать python-telegram-bot;
- сохранить /start, /help, /feedback, /skip, /cancel, /report, /myid, /training и /department;
- сохранить работу SQLite;
- сохранить DATA_DIR для Railway Volume;
- сохранить BOT_TOKEN и ADMIN_ID в переменных окружения;
- сохранить обработку ошибок CSV;
- добавить обработку callback-запросов от inline-кнопок;
- обновить текст /start и /help, если это необходимо;
- код должен оставаться понятным и содержать комментарии на русском языке;
- не добавлять лишние внешние библиотеки, если задача решается текущим стеком.
